# P1: 2026 runoff programme scenarios

- Owner: Claude (mapping, `config/programs_2026.yaml`), Codex builds model extensions, Claude reviews
- Depends on: C1, C2, C4, C5, C6; D1 to run, D2 back-test gate before any result is published
- Output: `src/programs.py`, scenario rows `P_lula`, `P_flavio` in D1 outputs

## Why
The two runoff programmes (Lula, PT; Flávio Bolsonaro, PL) propose different fiscal rules, tax changes, spending compositions and privatisation. The model must represent each with the same machinery and the same evidence standard, so the comparison reflects the policies, not the modelling.

## What to do
1. Implement the mechanisms listed in `config/programs_2026.yaml` -> `model_gaps_found`:
   - revenue path dimension with the Sanches et al. revenue multiplier;
   - rule-based spending paths: LC 200/2023 band rule (Lula) and a debt-stabilising primary-balance rule reached in T years (Flávio);
   - explicit minimum-wage rule in C1 pension indexation (current law for both);
   - privatisation: one-off debt reduction from asset sales plus `privatisation_wage_effects`.
2. Build scenarios `P_lula` and `P_flavio` from the items, sampling every `size_source: assumption` range uniformly and reporting it as an assumption.
3. Report each programme item's contribution (switch one item off at a time), so readers see which assumption drives a result.
4. Same parameter draws and external paths for both scenarios in every draw.

## Rules
- Neutrality rules at the top of `config/programs_2026.yaml` are binding.
- Never publish programme results before the D2 back-test passes.
- One branch per task (`task/p1`), tests for every mechanism.
- Never invent, interpolate or fill missing values without a source; mark assumptions as assumptions.
